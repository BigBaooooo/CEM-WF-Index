# CEM-WF-Index Final Paper-Review Code

This repository provides the source code component of the final CEM-WF-Index paper review artifact. The repository is organized around the final calibrated analogue-retrieval method described in the paper. The repository focuses on the Python implementation of the final method, while large datasets and generated artifacts are managed outside GitHub due to size and distribution constraints.

## Repository Layout

```text
cem_wf_index/
  final_release/
    offline_lambdarank.py      # offline calibration and grouped LambdaRank training
    online_inference.py        # final online retrieval/ranking reference implementation
    graph_features.py          # train-label graph activation and propagation features
    candidate_rows.py          # candidate-detail loading, relevance sets, anchor merge
    ranking_utils.py           # Recall, nDCG, mAP, and ranked-list helpers
    physical_errors.py         # evaluation-only typhoon physical consistency metrics
    asset_projection.py        # optional projection from regenerated outputs to paper assets
scripts/
  run_final_label_graph_lambdarank.py   # thin CLI wrapper around final_release.offline_lambdarank
  project_final_lambdarank_assets.py    # thin CLI wrapper around final_release.asset_projection
online/
  final_online_inference_reference.py   # compatibility wrapper around final_release.online_inference
tests/
  test_source_release_structure.py      # lightweight source-release checks
```

The implementation is intentionally version-neutral at the public package level. Historical experiment names are not required to understand or run the final release.

## What Is Included

- Final offline training/calibration logic for the label-graph LambdaRank full-candidate ranker.
- Final online inference reference logic for candidate scoring, graph propagation features, score blending, and anchor-preserving top-20 output.
- Minimal shared utilities required by the final method: ranking metrics, candidate-row handling, graph features, and evaluation-only physical error computation.
- Lightweight tests that verify the source release structure and policy flags without requiring experiment data.

## What Is Not Included

Large external datasets and regenerated intermediate artifacts are not distributed through GitHub. These include ERA5 raw data, CMA-STI crop data, derived feature tables, candidate-detail tables, generated result tables, figures, model checkpoints, and caches. These artifacts are handled outside the repository because of their size and storage/distribution requirements. End-to-end offline reproduction requires locally prepared datasets and regenerated intermediate files following the data contract described below.

## Method Boundary

The final method is a calibrated analogue-retrieval pipeline with supervised ranker calibration on the training split. Supervised labels from the training split are used only for ranker calibration. The validation split is used only for model/profile selection. The selected profile is frozen before any test-set ranking or metric reporting. During online or test-time inference, candidate scoring and ranking use only inference-available features, frozen train-label graph assets, and the frozen ranker/blend profile; no validation or test ground-truth labels are accessed.

## Python Environment

Use a Python environment with the scientific stack required by the final scripts. The project was developed with a Conda environment named `cemwf`, but the repository does not require that exact name.

Required packages include:

```text
numpy
pandas
scikit-learn
lightgbm
pytest
```

## Quick Checks Without Data

Run these commands from the repository root:

```bash
python -m compileall cem_wf_index scripts online tests
python -m pytest -q
python -c "from cem_wf_index.final_release import METHOD_DEFINITION, SELECTED_PROFILE; print(METHOD_DEFINITION, SELECTED_PROFILE)"
```

These lightweight checks validate source structure and imports. Full result reproduction requires the locally prepared datasets and intermediate artifacts described in the data contract.

## Offline Reproduction Entrypoint

After preparing the required candidate-detail files and supporting evaluation files locally, inspect the offline entrypoint:

```bash
python scripts/run_final_label_graph_lambdarank.py --help
```

The offline entrypoint trains the final grouped LambdaRank profile over candidate rows, builds train-label graph features, selects the profile on validation, and reports test metrics only after selection.

## Online Inference Entrypoint

The online reference implementation is available as a package module:

```bash
python -c "from cem_wf_index.final_release.online_inference import rank_candidates_online; print(rank_candidates_online)"
```

It takes a query event, a candidate pool generated by the upstream pipeline, frozen train-label graph assets, and a frozen ranker/blend profile as inputs.

## Expected Data Contract

The final offline pipeline expects locally generated candidate-detail tables with query IDs, candidate IDs, split roles, candidate source ranks/scores, relevance labels for training/validation evaluation, and the inference-available feature columns used by the final paper pipeline. Physical-error reporting additionally requires evaluation-only CMA best-track files and ERA5 tracklet-to-CMA mapping files generated according to the same local data-preparation pipeline. These files are not included in this source-code-only release.

## Review Notes

- This repository is the source-code component of the paper-review artifact.
- It provides the final method implementation used for the paper-review artifact.
- Paper results can be regenerated from locally prepared datasets and intermediate artifacts following the documented data contract.
